# Supplied social review library

`src/features/bna-communications/social-candidates.json` contains all34 bilingual posts from section11 of package `BNA-JLFA-IMPLEMENTATION-20261029-10`: 24 educational contributions, four co-op invitations, four Fishing invitations and two support invitations. The source and each bilingual body have SHA256 bindings. Source line endings are normalized to LF and only leading/trailing body blank lines are removed; copy and asset instructions are preserved.

`previewBnaSocialCandidate` produces plain text and canonical localized CTA paths with bounded campaign codes and a stable source content ID. It never accepts an arbitrary destination URL. Every result remains a review candidate, not queued, with live-destination and group-rule checks still required. A value post has no inferred placement business, and the library does not declare any post non-promotional under a group's rules. An asset instruction is not an approved asset binding.

This is preparation for the existing Marketing workflow, not another contact database or publication runtime. There is no sender, approval action, group scrape, Page connection, queue, cron or provider call here. The existing Windows preparation task still uses the superseded five-per-day/30-day planner and has its readiness gate closed; it must adopt the master's rolling seven-day cross-program promotion allowance, up to two distinct permitted educational contributions, spacing and preserved unknown/pending outcomes before that gate opens. Group publication remains supported/manual unless a specific permitted capability is established. Page scheduling requires the actual authorized channel and exact content/asset approval.
