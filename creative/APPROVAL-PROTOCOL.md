# Inner Leadership — Creative Approval Protocol

The user should not have to manually manage filenames, versions or folders.

## Natural-language commands

### “I like this.” / “This is good.” / “Keep this style.”

Treat as **APPROVED REFERENCE**.

- File in the correct category as a reference.
- Extract the approved qualities into `BRAND-MEMORY.md`.
- Do not automatically replace the CURRENT production asset unless it fills the same slot and the user says to use it.

### “This is the one.” / “Use this.” / “This is final.”

Treat as **CURRENT** for the exact asset slot.

1. Preserve the source/original.
2. Move the previous CURRENT version to HISTORY.
3. Promote the new asset to CURRENT.
4. Never delete prior approved versions.
5. Save the reproducible prompt/instructions when available.
6. Update `ASSET-REGISTRY.md`.
7. Update `BRAND-MEMORY.md` with why it was approved.

### “I don’t like this.”

- Do not promote it.
- If the reason reflects a stable preference, add the lesson to the avoid/preference section of Brand Memory.
- Do not over-generalize a one-off rejection.

### “I like this, but change X.”

- Preserve the liked version as the base/reference.
- Create the next numbered WORKING version.
- Change only the requested dimension unless dependencies require another change.
- Do not overwrite the liked version.

### “Make another one like the approved landing-page images.”

Read in this order:

1. `BRAND-MEMORY.md`
2. `ASSET-REGISTRY.md`
3. CURRENT assets for Landing Page
4. Relevant APPROVED REFERENCES if needed
5. Current brief

Do not automatically read every historical asset.

### “Organize these.”

- Unreviewed = Inbox or category `00_WORKING`.
- Do not infer approval from existence.
- If category is unclear, Inbox is safer than guessing.

### “Archive this.”

- Previously approved = category HISTORY.
- Retired/non-current non-canonical material = `99_ARCHIVE`.
- Never delete unless explicitly asked.

## Standard creative-heavy category structure

```text
00_WORKING
01_CURRENT — Approved
02_HISTORY — Prior Approved
03_PROMPTS — Reproducible
```

Use the same pattern when a new creative category becomes active.

## Versioning

Version the **asset slot**, not the whole business.

Examples:

- `landing.hero`: v01 → v02 → v03
- `meta.critical-thinking.square`: v01 → v02
- `curriculum.communication`: v01 → v02

Preferred filename:

`IL_<category>_<asset-slot>_vNN_<status>.<ext>`

## No duplication

Keep one canonical approved copy in its functional Drive category. Use the registry to reference it elsewhere rather than copying the same asset into many folders.

## Real-media rule

Original real photographs live in:

`05_REAL MEDIA — Originals & Consent / 01_ORIGINALS — Never Modify`

Do not overwrite them. Public/cropped versions are separate derivatives. Real child media is not promoted to “Approved for Public” solely because it is a good image; public-use permission is a separate state.

## Memory principle

**The asset is evidence. The reason the user liked it is the reusable preference. Save both.**
