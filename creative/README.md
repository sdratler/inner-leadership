# Life Skills graphics: native packages and one library

**The selected approved image bytes are the visual authority. A prompt is a job request, not a replacement master.**

## Current workflow

The owner produces graphics with native ChatGPT in self-contained packages of up to ten clearly enumerated output jobs. Packages cover disjoint concept ranges; a concept’s languages and formats are separate derivatives. Each package includes the actual approved composition rasters and needed source photo/logo files, the exact copy, permitted changes, target dimensions and a checkpoint. Reference files must be opened and supplied through the supported image-edit path; a filename or URL alone is not input binding.

Codex prepares packages, receives actual results, verifies file identity/dimensions, performs separately documented mechanical exports, and updates the existing graphics register. Image-producing windows do not claim spreadsheet rows, operate the app, or manage publication. If the image tool ends a turn, Continue resumes the previous result and next pending job; it never restarts completed work.

**OpenArt is historical provenance only, not the current production route. No new paid generation or fallback is authorized by this README.** Do not restart completed website heroes, the owner-completed Facebook cover, or an existing monthly set from an obsolete missing label.

## Asset rules

Feed delivery is1080×1350. Status/Story delivery is1080×1920, using a separately composed vertical source. Never stretch a feed into Status or crop away people, logo, service, benefits or contact details. Keep native originals and delivery exports distinct and record any proportional resize/padding transformation.

Preserve approved photograph, logo, typography and layout where they are not the requested edit. Use the actual single-leaf artwork, not a redraw or an extra logo. No replacement people or invented English tagline. Preserve exact approved logo-language exceptions in existing files; housekeeping is not permission to revise their pixels.

Acceptance binds an exact file/version/hash or an explicitly documented template-run scope. REVIEW in an old filename does not cancel later approval; APPROVED in a filename does not create it. File existence and matching dimensions are not visual QA. New bytes do not inherit an unrelated approval. Rejected/discarded exact files remain excluded even if copies survive in archives.
